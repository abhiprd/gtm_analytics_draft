# Testing & Experimentation Platform

## What this is

A shared, reusable engine for evaluating any test the company runs — a new pricing page test, a new onboarding flow, a messaging change, whatever comes next — instead of someone hand-computing the results of each new test from scratch. It measures whether the group that got the change actually beat the group that didn't by a real, statistically meaningful margin, checks that nothing important broke as a side effect (a guardrail), and confirms there were enough people in the test for the result to be trustworthy in the first place. It's built for RevOps, growth, and marketing leadership who need every future test read the same rigorous, consistent way, not re-analyzed from scratch each time one comes up.

## Why it exists

The company's growth framework already leans on one real controlled test — the marketing holdout program that measures how much of paid and community advertising's contribution is genuine, causal lift rather than credit assigned after the fact — to validate part of the channel-mix picture leadership already reports against. As the business runs more tests going forward, leadership needs a standing, trusted way to read every one of them the same way, rather than a fresh, one-off analysis reinvented each time with no guarantee two different tests were evaluated by the same standard. This asset is built as that standing piece of infrastructure, not as an analysis of the one test that happens to exist today.

## How it works

For any test that's been properly registered — what it's testing, who's in the treatment group, who's in the control group, and what result it's supposed to move — the tool compares how often the outcome being tracked actually happened in each group, then runs a standard statistical check to determine whether that gap is large enough, given how many people were involved, to be trusted as a real effect rather than random noise. Alongside that, it checks a small set of guardrail metrics to confirm nothing important broke as a side effect of the test, and it reports whether the number of people in the test was actually large enough for the result to be a meaningful read rather than a coin flip dressed up as a finding. Before any of that runs, it also does a basic quality check on the test's own definition — does it have a real hypothesis, a real, clearly defined control group, a stated target metric, and so on — so a poorly-defined test gets caught and flagged before anyone wastes time running numbers on it.

## Key decisions and why

- **This was built as a reusable, general-purpose engine, not a write-up of the one test that exists today.** Rather than a fresh analysis for every new test the company runs, registering a test once lets the same trusted engine evaluate it — and every test after it — the same way, with no risk of two tests being read by two different, ad-hoc standards.
- **The engine's trustworthiness is proven by having it independently reproduce a result the company already knows the correct answer to, rather than trusted on faith.** The company's one completed randomized test — the marketing holdout program — already has a published, trusted result. Before this tool is applied to anything new, it's pointed at that known-answer case, calculates the result entirely on its own straight from the underlying records, and checks whether it lands on the same answer. It does, to within ordinary rounding — which is what earns it the standing to be trusted on the next test.
- **That check counts as a genuine second opinion because it never reuses or calls into the original calculation.** Every formula this tool needs was built independently from the tool that produced the marketing holdout's original published result, so a match between the two is real confirmation the answer is right, not two copies of the same calculation quietly agreeing with itself.
- **A straightforward, directly-measured statistical comparison was used instead of a more complex modeled estimate.** The company's one real test is a genuine randomized experiment — people were split into a treatment and control group by chance, and results are compared directly. Replacing that direct comparison with a modeled, statistically-estimated stand-in would trade a real, directly-measured cause-and-effect answer for a modeled guess at the same thing.
- **A more advanced statistical adjustment technique was considered and set aside for now, since it would sharpen precision rather than correctness.** That kind of refinement could someday narrow the margin of error further on a result, but the more important bar for a brand-new evaluation engine is getting an already-known answer right, which the current approach already does. It remains a candidate upgrade once a future test genuinely needs the extra precision.
- **The engine handles a fully finished test and one still actively collecting people exactly the same way, using the same time-aware logic.** A person who simply hasn't had enough time yet to reach the tracked outcome is kept out of the result entirely, rather than being counted as a "no" — so the tool never mistakes "too early to tell" for "didn't work," whether it's checking in on a test mid-flight or reading one that's long since closed.
- **Registering a future test only requires pointing the engine at where that specific test's outcome data lives, not rebuilding any of the underlying statistics.** The core math — the significance check, the guardrail check, the sample-size check — works the same way for any test; the only new work a future test needs is one small connector telling the engine which records hold its results.
- **A basic quality check runs on every registered test before its results are ever evaluated.** It looks for the essentials a real test needs — a stated hypothesis, a defined control group, a stated target metric, defined guardrails, and real people actually split across both groups — and names anything missing individually, so a poorly-defined test is caught before anyone spends time running numbers on it. This check only confirms a test was filled out completely, not that its design is logically sound; a human review still decides whether a complete test is also a well-designed one.
- **The safety threshold for one guardrail — how much crossover between the test and control groups is tolerable — is this tool's own first-pass proposal, not an inherited standard.** It's set comfortably above the crossover level actually observed in the one real test today, while still tight enough to catch a genuine breakdown in group separation, and is flagged for independent review before being treated as final.

## What drives the result

- **A real test registration** — a stated hypothesis, a defined treatment group and control group, how people were actually assigned to each, a target metric, and any guardrail metrics
- **A real record of who was actually assigned to each group**, not just the plan on paper
- **The core comparison** — how often the tracked outcome happened in the group that got the change versus the group that didn't
- **A significance check** — whether that gap is large enough, given how many people were in each group, to be trusted as a real effect rather than random noise
- **Guardrail checks** — for the one real test evaluated today, whether the untouched comparison group stayed large enough to be meaningful, and whether anyone meant to be held back from the campaign was accidentally exposed to it anyway
- **Timing discipline** — a person only counts toward a result once they've had a fair amount of time to reach the tracked outcome, so someone who simply hasn't had time yet isn't miscounted as a non-result
- **A sample-size check** — whether the number of people in each group was actually large enough to reliably catch the size of effect being looked for, and the smallest effect that group size could reliably have detected

## Current result

As of December 31, 2025, this framework has been run against the one real, completed test the company has on record — the marketing holdout program that measures how much of paid and community advertising's contribution is genuine, causal lift. Recalculating that test's result completely independently, the framework landed on essentially the same answer already published elsewhere: an incremental lift of about 68.2%, with a significance score comfortably clearing the conventional bar for treating a result as real rather than chance (a score of about 4.43 against a typical bar of roughly 2). The two figures differ by an amount smaller than the rounding already built into how the original result was reported — the level of agreement this tool needs to earn trust for the next test. Re-running the same check at an earlier point in time (mid-2025) produced an internally consistent, if different, read, confirming the framework behaves correctly at any point in a test's life, not only once everything has fully wrapped up.

The one guardrail on this test with a hard numeric floor — keeping the untouched comparison group large enough to be meaningful — passed with more than three times the required minimum. The second guardrail, watching for people held back from the campaign who ended up seeing it anyway, found this happened to roughly 1 in 100 of them, comfortably under this tool's own proposed ceiling. The test's group sizes were also large enough to have reliably caught an effect roughly a third smaller than what was actually found, meaning the result is not a narrow, borderline call.

The registration-quality check confirms the one test on the books today is fully and correctly defined. The tool's own five built-in self-tests — deliberately feeding it both a well-formed and a broken made-up test definition — all correctly told the two apart, including naming each specific missing piece in the broken one.

## Known limitations

- **Every new test still needs one small piece of manual setup before the engine can evaluate it.** A plain-English description of what a test is measuring isn't enough for a computer to know exactly where that test's results live in the underlying data, so someone has to point the tool at the right place the first time a new test is registered. This isn't a shortcut still to be closed — it's the honest, permanent boundary between the general math (which never changes) and the wiring for any one specific test (which always will).
- **The tool currently assumes every test has exactly two groups — a treatment group and a clearly labeled control group** — matching how every test is run today. A future test comparing three or more groups at once would need the tool extended first; it's built to flag that case rather than guess at an answer it isn't designed to give.
- **The registration-quality check only confirms a test's paperwork is filled in, not that what's written actually makes sense.** A control group description that's nonsensical, or that accidentally describes the same population as the treatment group, would still pass. A human review remains the real safeguard for whether a complete test definition is also a sound one.
- **This framework has only ever been proven against one real, completed test, because that's the only one the company has run so far.** Its confidence in handling a future, differently-shaped test rests on how generally the underlying math was built, not on having actually been exercised against a second real case yet.
- **No new data was added anywhere in the underlying systems to build this tool.** It reads entirely from test records and results that already existed.
